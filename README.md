# AmneziaWG 3.1 + веб-панель

Установщик сервера AmneziaWG 3.1 и лёгкая веб-панель для управления клиентами.

## Установка на сервер (Ubuntu 20.04+ / Debian 11+)

```bash
ssh root@<IP_СЕРВЕРА>
git clone -b claude/amnesiawg-web-panel-1kuz00 https://github.com/g79175929220-tech/amneziawg.git
cd amneziawg
sudo bash install.sh   # опции: --port --panel-port --endpoint --proto 3|2|1 --iface --subnet
```

В конце скрипт выведет адрес панели (`https://<IP>:8443`), логин `admin` и сгенерированный пароль.

### Что ставится

**AmneziaWG 3.1** (`amneziawg-go v3.1.20260828` + `amneziawg-tools v3.1.20260812`) собирается из
исходников в изолированный каталог `/opt/awg3`, конфиги лежат в `/etc/awg3`, сервис — `awg3-quick@awg3`.
Используется userspace-реализация amneziawg-go, поэтому модуль ядра не нужен и не трогается.

Параметры 3.x, которые генерирует панель:
- `HeaderProtectionKey` — шифрование заголовков пакетов (поэтому S1–S4 ≥ 12);
- `ContentPaddingAddition` — случайное дополнение пакетов с данными;
- `RandomTrailers` (3.1) — случайный «хвост» у каждого пакета, **должен совпадать на сервере и клиенте**;
- `DisableCookies` (3.1) — только для сервера, в клиентский конфиг не попадает;
- плюс всё из 2.x: Jc/Jmin/Jmax, S1–S4, диапазоны H1–H4, I1–I5.

Клиенту нужно приложение с поддержкой AmneziaWG 3.x: старые клиенты 2.0 к такому серверу не подключатся.
Для совместимости со старыми клиентами можно поставить `--proto 2`.

### Установка рядом с уже работающим AmneziaWG 2.0

Существующий туннель (на хосте или в Docker-контейнере AmneziaVPN) не затрагивается:
- системные `awg`/`awg-quick` и модуль ядра не заменяются — у 3.1 свои бинарники в `/opt/awg3`;
- существующие интерфейсы (`awg0`, `wg0`, контейнеры `amnezia-*`) не трогаются;
- свободные интерфейс (`awg3`, …), UDP-порт и подсеть (`10.9.0.0/24`, …) подбираются автоматически;
- можно задать вручную: `--iface awg3 --port 51821 --subnet 10.20.0.0/24`.

## Панель

- список клиентов: онлайн-статус, последний handshake, трафик Rx/Tx;
- **группы-вкладки** с количеством: все / платные / тест / истекают (≤ 7 дней) / отключённые;
  метка **ТЕСТ** (ставится пресетом «Тест · 5 дн», снимается продлением на месяцы)
  и **заметка** к клиенту (контакт, оплата) — по ней работает поиск;
- сортировка: по дате создания, окончанию срока, имени, трафику;
- добавление / отключение / удаление / переименование клиента без перезапуска туннеля, поиск;
- QR-код и файл **`.vpn`** для AmneziaVPN (на телефоне открывается в приложении по нажатию;
  внутри обычная конфигурация AmneziaWG — AmneziaVPN определяет формат по содержимому),
  а для отдельного приложения AmneziaWG — `.conf` (ссылка в окне QR-кода).
  Файлы отдаются как `application/octet-stream`, поэтому телефоны не дописывают `.txt`;
- настройки endpoint, порта, DNS, MTU, keepalive;
- **лимиты трафика** на клиента — всего или в месяц (сброс 1-го числа); при превышении клиент
  отключается автоматически, после повышения лимита или сброса счётчика включается обратно.
  Трафик учитывается накопительно и не теряется при перезапуске туннеля или отключении клиента;
  проверка идёт раз в 15 секунд, поэтому лимит может быть превышен на объём, скачанный за это время;
- **одноразовые ссылки** на конфигурацию (действуют 1 час / 24 часа / 7 дней): получатель
  без входа в панель один раз видит QR-код и файл. Превью в мессенджерах ссылку не гасят —
  конфиг выдаётся только по нажатию кнопки. Новая ссылка отменяет прежнюю,
  в `state.json` хранится только хеш токена. Для ссылки сразу показывается её QR-код:
  кнопки «Копировать картинку» (вставить в чат) и «Скачать PNG» — карточка с именем клиента,
  QR-кодом и сроком действия ссылки, клиент наводит на неё камеру телефона;
- срок действия клиента с автоотключением и **калькулятор дат**: при создании — кнопки
  «Тест · 5 дн» для пробного доступа и 1 / 3 / 6 / 12 месяцев (по умолчанию 6, меняется в настройках), в «Ограничениях» —
  «+N мес» от текущего окончания (оплатил заранее — дни не теряются) или от сегодня, если срок истёк;
- редактирование и перегенерация параметров обфускации;
- смена пароля, защита от перебора и CSRF.

## Резервные копии и перенос на другой сервер

Каждую ночь в 03:00 (часовой пояс — в настройках, по умолчанию Москва) панель сохраняет архив
с клиентами, ключами и настройками в `/var/backups/awg-panel`, хранятся последние 14.
В **Настройки → Резервные копии** — список копий, «Скачать» и «Сделать копию сейчас».

Перенос на новый сервер (ключи клиентов и сервера сохраняются):

```bash
git clone -b claude/amnesiawg-web-panel-1kuz00 https://github.com/g79175929220-tech/amneziawg.git
cd amneziawg && sudo bash install.sh --restore /root/awg-backup-20261013-030000.tar.gz
```

Чтобы переезд проходил незаметно для клиентов, Endpoint должен быть **доменом**: `cert.sh` ставит
его сам. Клиенты, у которых на устройстве конфиг со старым адресом, помечены в списке
«старый конфиг» — им конфиг нужно выдать заново один раз.

Если в настройках Endpoint был **доменом** (например, `amnezvpm.duckdns.org`), достаточно перевести
домен на новый IP — клиентам ничего менять не нужно. Если Endpoint был IP-адресом, установщик
заменит его на новый, и клиентам нужно заново скачать конфиг.

## Уведомления в Telegram

**Настройки → Уведомления в Telegram**: создайте бота у @BotFather, нажмите в нём «Старт»,
вставьте токен → «Найти мой chat id» → «Отправить тест». Бот присылает:
- утреннюю сводку (час настраивается): кто истекает в ближайшие 3 дня, кто отключился за сутки;
- сразу: клиент отключён по сроку или лимиту, туннель не отвечает / снова работает;
- по желанию — ночную резервную копию (в ней ключи всех клиентов: только в личный чат с ботом).

Если упадёт сама панель, она не сможет об этом сообщить — для этого нужен внешний мониторинг.

## Безопасность

### Двухфакторный вход в панель
**Настройки → Двухфакторный вход → Включить**: отсканируйте QR-код в Google Authenticator / Яндекс Ключе,
введите код и сохраните 8 запасных кодов. После этого при входе, кроме пароля, нужен код с телефона.
Потеряли телефон и коды: `/opt/awg-panel/venv/bin/python /opt/awg-panel/app.py disable-2fa`.

### Защита SSH (`secure-ssh.sh`)
fail2ban банит IP после 5 неудачных попыток входа, вход в SSH — только по ключу.

1. Ключ в Windows: **PuTTYgen** → EdDSA (Ed25519) → Generate → «Save private key» (.ppk) →
   скопируйте строку из поля «Public key for pasting into OpenSSH authorized_keys file».
2. На сервере:
   ```bash
   curl -fsSLO https://raw.githubusercontent.com/g79175929220-tech/amneziawg/claude/amnesiawg-web-panel-1kuz00/secure-ssh.sh
   bash secure-ssh.sh --add-key "ssh-ed25519 AAAA... (ваша строка)"
   ```
3. Не закрывая окно, откройте новое окно PuTTY с ключом (Connection → SSH → Auth → Credentials → .ppk).
   Вошли — `bash secure-ssh.sh --confirm`. Не вошли — `bash secure-ssh.sh --rollback`
   (или подождите 10 минут: вход по паролю вернётся сам).

Без ключа скрипт ставит только fail2ban и пароли не отключает. Ваш текущий IP fail2ban не банит.
Состояние: `bash secure-ssh.sh --status`.

## Официальный сертификат для панели (вместо самоподписанного)

Бесплатный сертификат Let's Encrypt выдаётся на домен, поэтому нужен домен, указывающий на сервер:
бесплатный поддомен [duckdns.org](https://www.duckdns.org) (например, `myvpn.duckdns.org` → IP сервера)
или свой домен с A-записью на IP сервера. Затем на сервере:

```bash
cd ~/amneziawg && git pull
sudo bash cert.sh myvpn.duckdns.org            # можно добавить --email you@mail.ru
```

Скрипт проверит, что домен указывает на этот сервер и порт 80/tcp свободен (по нему Let's Encrypt
проверяет домен — откройте его и в файрволе хостинга), получит сертификат, подключит его к панели
и настроит автопродление, а домен станет Endpoint в конфигах клиентов (`--keep-endpoint` — не менять).
Панель будет доступна по `https://myvpn.duckdns.org:8443` без предупреждений,
одноразовые ссылки тоже будут с доменом. Вернуть самоподписанный: `sudo bash cert.sh --self-signed`.

## Каскад (для мобильного интернета)

Если с мобильного интернета подключение работает плохо (операторы режут или замедляют UDP к
зарубежным IP, а во время ограничений пропускают только российские адреса), трафик можно пустить
через промежуточный — входной — сервер, например в РФ:

```
телефон ──► входной сервер (РФ) ──► этот сервер с AmneziaWG ──► интернет
```

Входной сервер только пересылает UDP-пакеты (DNAT): AmneziaWG на нём не нужен, ключей там нет,
обфускация сохраняется на всём пути.

1. На входном сервере (любой VPS с Ubuntu/Debian):
   ```bash
   git clone -b claude/amnesiawg-web-panel-1kuz00 https://github.com/g79175929220-tech/amneziawg.git
   sudo bash amneziawg/cascade/entry.sh --exit <IP_этого_сервера>:51820 --port 443
   ```
   `--port 443` — входной сервер слушает UDP 443 (как QUIC/HTTP3): такой трафик операторы трогают реже.
   Правила лежат в собственных цепочках `AWG_CASCADE_*`, переживают перезагрузку и не мешают Docker/ufw.
   Один входной сервер может вести на несколько выходных — каждый маршрут на своём порту:
   `bash entry.sh --exit <IP_второго>:51820 --port 8443`. Добавление маршрута не обрывает
   подключённых клиентов. Статус: `--status`, удаление: `--remove 8443` (все: `--remove all`).
2. В панели: **Настройки → Адрес каскада** = `<IP_входного>:443`.
3. У нужных клиентов в окне QR-кода выберите **«Через каскад»** (или сразу при создании) и
   заново импортируйте конфиг на устройстве. Остальные клиенты продолжают подключаться напрямую.

Если проблема остаётся, попробуйте уменьшить MTU до 1280 в настройках — у мобильных сетей он часто меньше.

## Файлы на сервере

| Путь | Назначение |
|---|---|
| `/etc/awg-panel/state.json` | ключи, клиенты, параметры (источник истины) |
| `/etc/awg-panel/panel.json` | логин/хеш пароля панели |
| `/etc/awg3/awg3.conf` | генерируется панелью, вручную не править |
| `/opt/awg3/bin` | `awg`, `awg-quick`, `amneziawg-go` версии 3.1 |

## Полезные команды

```bash
/opt/awg3/bin/awg show awg3                 # состояние туннеля 3.1
systemctl status awg3-quick@awg3 awg-panel
/opt/awg-panel/venv/bin/python /opt/awg-panel/app.py set-password 'НовыйПароль'
```

Для команд `app.py` вне панели нужны переменные окружения: `set -a; . /etc/awg-panel/panel.env; set +a`.

Рекомендуется ограничить доступ к порту панели (например, `ufw allow from <ваш IP> to any port 8443`).
